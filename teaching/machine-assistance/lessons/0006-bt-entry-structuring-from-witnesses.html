BT Entry Structuring From Witnesses

This lesson shows how to go from a Bosworth-Toller OCR witness page to structured, machine-readable dictionary entries without flattening away the evidence that makes the entry trustworthy.

Win for today: by the end, you should be able to explain why the unit of work is an entry block rather than a page, and sketch a schema plus a parsing workflow using abbad as the worked example.

1. The Unit Of Work Is The Entry

For Bosworth-Toller, page OCR is only the witness layer. The useful structuring unit is the entry block: one headword plus its variants, grammar, glosses, attestations, citations, derivations, and editorial material.

Do not start by asking: “How do I turn this whole page into final rows?”

Start by asking: “Where does one entry start, where does it end, and how do I preserve all the fragments inside it?”

2. The Witness We Start From

For this lesson, the source page is anglosaxondictio00bosw-0030.png, split into tiles such as anglosaxondictio00bosw-0030-col-1-part-1.png and anglosaxondictio00bosw-0030-col-2-part-1.png, with the reassembled OCR witness in anglosaxondictio00bosw-0030.md.

That witness already gives us strong clues:

  • new entries begin with a bold-like headword shape at the start of a line in the page image
  • the witness preserves many variant spellings inline
  • grammar often appears early, in patterns like es; m. or an; f.
  • definitions, Latin glosses, and attestations are mixed into one block rather than clean columns

3. First Goal: A Lossless Raw Entry

Before you build a final dictionary schema, build a lossless raw entry representation. This is where you preserve order and provenance.

Fragment typeWhat it holds
headwordthe canonical displayed entry head
variantorthographic or inflectional alternatives listed near the head
grammarthings like es; m., an; f., verb principal-part hints, or inflection info
senseone meaning unit or numbered subentry
translation_enModern English gloss or explanation
translation_laLatin gloss when present
attestationquoted or cited Old English evidence
source_citationabbreviated source reference such as Bd., Chr., Cd.
editorial_notelong explanatory prose, etymology, or bracketed note
derivationDER. lists or related-form sections
unclassified_remainderanything you cannot safely classify yet

The win here is simple: nothing gets lost just because the parser does not yet fully understand it.

4. Worked Example: abbad

From the witness page, the abbad block begins around:

abbad, abbod, abbud, abbot, es; m.: abboda, an; m. I. an abbot; abbās,...

Even before perfect correction, we can already see several layers:

  • headword: abbad
  • variants: abbod, abbud, abbot
  • grammar: es; m. and abboda, an; m.
  • sense labels: I. and II.
  • Latin gloss: abbās
  • attestations and citations: lines beginning with quoted OE plus references like Bd. pref., Chr. 803, L.I.P. 13
  • editorial note: the long prose explanation of what an abbot is and how the title developed
  • derivations: DER. abbad-dôm, -hād, -isse, -ríce : abboda.

5. A Raw Entry Schema

This is the sort of schema to aim for first. Keep it permissive and evidence-friendly.

from pydantic import BaseModel, Field


class Citation(BaseModel):
    source: str | None = None
    locator: str | None = None
    quote_oe: str | None = None
    translation_en: str | None = None
    translation_la: str | None = None


class Sense(BaseModel):
    label: str | None = None
    definition_en: str | None = None
    definition_la: str | None = None
    notes: list[str] = Field(default_factory=list)
    citations: list[Citation] = Field(default_factory=list)


class RawFragment(BaseModel):
    kind: str
    text: str
    note: str | None = None


class DictionaryEntry(BaseModel):
    headword: str
    variants: list[str] = Field(default_factory=list)
    inflections: list[str] = Field(default_factory=list)
    part_of_speech: str | None = None
    grammatical_notes: list[str] = Field(default_factory=list)
    senses: list[Sense] = Field(default_factory=list)
    derivations: list[str] = Field(default_factory=list)
    editorial_notes: list[str] = Field(default_factory=list)
    raw_fragments: list[RawFragment] = Field(default_factory=list)
    unclassified_remainder: str | None = None

This schema is intentionally boring. That is good. It is stable enough for code, broad enough for partial parses, and explicit enough that you can tell what the parser does not yet know.

6. A First Structured Draft For abbad

{
  "headword": "abbad",
  "variants": ["abbod", "abbud", "abbot"],
  "inflections": ["es; m.", "abboda, an; m."],
  "part_of_speech": "noun",
  "grammatical_notes": ["masculine"],
  "senses": [
    {
      "label": "I",
      "definition_en": "an abbot",
      "definition_la": "abbās",
      "notes": [
        "title of the male superior of certain religious establishments",
        "long editorial explanation of historical monastic usage follows"
      ],
      "citations": [
        {
          "quote_oe": "Se árwurda abbad Albínus",
          "translation_en": "the reverend abbot Albinus",
          "source": "Bd.",
          "locator": "pref."
        }
      ]
    },
    {
      "label": "II",
      "definition_en": "bishops were sometimes subject to an abbot"
    }
  ],
  "derivations": ["abbad-dôm", "abbad-hād", "abbadisse", "abbad-ríce"],
  "editorial_notes": [
    "long prose note on the office and historical usage of abbots"
  ]
}

This is still not “final truth.” It is the first useful structured draft. The important thing is that the parser can emit this draft while still preserving the raw fragments that produced it.

7. What To Gold By Hand

Yes: there is still a gold step. But for BT the gold should be at the entry-structure level, not just page text.

Gold 1: one page witness correction, so the OCR text itself is trustworthy.
Gold 2: entry boundaries for that page.
Gold 3: hand-labeled fragments for 5-10 representative entries like abbad, abbadisse, and abbod-ríce.

That gives you real targets for:

  • entry-boundary accuracy
  • headword extraction accuracy
  • variant extraction accuracy
  • part-of-speech / grammar extraction accuracy
  • citation detection accuracy

8. Parsing Strategy: Deterministic First, AI Second

For BT, start with deterministic parsing. Use AI only for the residue.

First-pass deterministic cuesWhy they help
new line plus headword-like tokengood signal for entry starts
patterns like es; m., an; f.good grammar / inflection hooks
I., II., DER.good internal structure markers
citation abbreviations like Bd., Chr., Cd.good source-reference hooks
em dash / colon transitionsoften mark gloss or attestation boundaries

Good practical rule: deterministic code should get you a safe partial parse with leftovers. AI should help only with the leftovers, ambiguities, or review suggestions, not replace the base parser.

9. Where Pydantic Helps

pydantic is very useful here. It gives you:

  • a stable schema for entries, senses, citations, and fragments
  • validation of partial parses
  • clear optional vs. required fields
  • easy JSON export for later review or downstream agents

PydanticAI can be useful later, but not as the foundation. The foundation should still be explicit schemas plus gold examples. AI is better used for:

  • classifying unclassified fragments
  • proposing repairs for ambiguous entries
  • generating review suggestions

10. Recommended Startup Workflow

Step 1: choose one BT page and produce a trustworthy witness.
Step 2: hand-mark entry boundaries on that page.
Step 3: hand-annotate a handful of entries like abbad into fragments.
Step 4: write deterministic parsers against those examples.
Step 5: emit Pydantic-validated structured drafts with leftovers preserved.
Step 6: use AI only for the residue the deterministic parser cannot handle cleanly.

This keeps the system inspectable, measurable, and extensible. Most importantly, it lets you improve parsing without ever losing the witness layer.
