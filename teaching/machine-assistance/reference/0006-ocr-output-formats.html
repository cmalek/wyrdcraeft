OCR Output Formats

Use this page when you need to remember what hOCR, TSV, ALTO, and PAGE XML are actually for.

Quick rule: plain text is for reading, but these formats are for keeping layout, coordinates, structure, and confidence attached to the recognized text.

hOCR

hOCR is an OCR output format built on HTML/XHTML. It stores recognized text inside markup that can also carry bounding boxes, line structure, page structure, and sometimes confidence values.

Use it when: you want something human-inspectable, browser-friendly, and still rich enough to show where the text came from on the page.

Think of it as: OCR text plus page geometry in an HTML-shaped wrapper.

TSV

TSV means tab-separated values. In OCR output, it usually gives you one row per page, block, paragraph, line, or word, with columns for text, confidence, and coordinates.

Use it when: you want to script quickly, filter low-confidence words, compute simple layout statistics, or push OCR results into a dataframe without much ceremony.

Think of it as: the fastest low-friction format for analysis, but not the richest structural model.

ALTO

ALTO is an XML standard used widely in digitization and library settings. It represents pages, regions, lines, strings, coordinates, and metadata in a more formal archival structure.

Use it when: you want a richer, more standardized interchange format for OCR output in long-lived collections or digital-humanities pipelines.

Think of it as: archive-grade OCR XML.

PAGE XML

PAGE XML is another XML standard, especially common in OCR and document-analysis research. It is strong at representing page regions, text lines, segmentation, and reading order.

Use it when: layout structure itself is part of the problem, for example when you care about regions, line segmentation, table zones, or the exact reading order.

Think of it as: layout-analysis XML with OCR text attached.

Common OCR Quality Metrics

MetricWhat it meansBest useMain caution
CERCharacter Error Rate: the share of characters that must be inserted, deleted, or substituted to turn OCR output into the reference text.fine-grained text quality, especially for short forms, diacritics, and symbol-heavy materiala decent CER can still hide structurally important failures such as table collapse or lost italics
WERWord Error Rate: the share of words that must be inserted, deleted, or substituted to turn OCR output into the reference text.coarser readability checks and page-level comparisonsWER is less sensitive than CER to single-character damage inside a word, which matters a lot in philological work

Quick rule: use CER when character fidelity matters, and use WER when you want a rougher sense of how readable the recognized text is. For Old English and similar material, CER is usually the more informative of the two, because one wrong character can change morphology, script, or diacritics even when the word still looks close enough to a human reader.

Practical Caution

These formats do not solve OCR quality by themselves. They solve a different problem: they keep evidence about where the text came from and how it was segmented. That matters a lot when plain text looks plausible but the layout, reading order, or symbol handling may be wrong.
